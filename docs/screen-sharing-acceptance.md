# 桌面屏幕共享验收

更新日期：2026-09-12。

## 范围与结论

本轮实现整屏与窗口共享、顶部悬浮工具栏、共享范围绿色提示、暂停恢复、新共享切换、返回会议和停止共享。**批注排除，不新增批注入口、消息通道或绘制功能。**

**实现与本机自动化验证已完成；真实 Jitsi 双端会议和混合 DPI 多屏现场验收仍待补齐，不能据此签收全部用户场景。**

修改前的基线为 8 项隔离检查中 6 项失败。本次将共享控制迁移到独立会话模块，并将原检查入口更新为 20 项回归测试，覆盖对应问题及新增异常场景。原 main.js 的 100 毫秒延迟最小化逻辑迁入会话模块；点击返回会议会取消该延迟。

## 最终实现

- 整屏与窗口共享均创建顶部工具栏，显示共享对象；空闲约 1.8 秒收起，移入或键盘聚焦展开，通过左侧手柄拖动。
- 工具栏包含麦克风、摄像头、成员、新的共享、暂停/恢复、返回会议、结束共享七个入口。会议控制复用 Web 页创建的 Jitsi External API，状态定期同步。
- 返回会议保留工具栏和范围提示。结束共享、源关闭、采集页面导航、会议关闭时回收资源。
- 屏幕源使用 display_id 匹配显示器。Windows 窗口源通过隐藏的 PowerShell/DWM 辅助进程每 200 毫秒读取窗口范围，转换为 Electron DIP；窗口隐藏或最小化时隐藏绿框，工具栏提示目标隐藏。
- 暂停保留同一输出视频轨道，冻结最后画面并在输出画面上显示“共享已暂停”；恢复后继续原源。按推荐默认策略同时暂停共享电脑声音，麦克风不变。
- 新共享先选择再采集候选源，候选首帧就绪后才替换原输入；输出轨道保持不变。取消、权限失败、候选画面失败会保留原源和原暂停状态。
- 采集、首帧和控制通信有超时；过期切源不能在页面恢复后迟到执行。错误反馈后恢复可操作状态。选择器打开期间仍可结束共享。
- 用独立沙箱预加载在嵌套 iframe 中接入采集。远程 iframe 不获得原壳的文件/窗口接口，也不获得 Node API。未修改 Web 项目源码。

## 可复现验证

逻辑与生命周期测试（20 项）：

```powershell
node scripts/check-share-acceptance.cjs
```

Electron 原生集成测试：

```powershell
$verification = Start-Process -FilePath '.\node_modules\electron\dist\electron.exe' -ArgumentList 'scripts/verify-share-electron.cjs' -WindowStyle Hidden -PassThru -Wait -RedirectStandardOutput 'docs/share-native-test.stdout.log' -RedirectStandardError 'docs/share-native-test.stderr.log'
$verification.ExitCode
```

原生脚本只用本地 HTTP 测试页面、合成画面与本机 WebRTC 对等连接，不连接外部会议，不采集桌面、麦克风或摄像头。四组检查通过：

1. 沙箱采集预加载进入嵌套 iframe，但未暴露 Node 或壳接口。
2. WebRTC 接收端看到红色初始帧、红色暂停帧、绿色恢复帧、蓝色新源；切源失败后仍为蓝色；sender track 不变。
3. Electron 实际加载七个工具栏按钮，布局无横向溢出。
4. Windows 辅助脚本能编译并识别真实隐藏 Electron 窗口。

原生环境 GPU 进程曾退出，因此**仅测试脚本启用软件渲染**；应用默认 GPU 策略未改。该结果不覆盖硬件加速下的性能和兼容性。

## 实现边界

- Windows 已实现窗口边框跟随；其他平台保留共享控制，但不承诺窗口范围跟随，工具栏会显示能力提示。
- 暂停仍保留本地原始采集，冻结的是发布画面；共享音频通过独立增益静音，麦克风不受影响。
- 若本次会议采集请求没有建立音频轨道，切源不能凭空向 Jitsi 新增已发布的音频轨道；选择电脑声音时会提示重新开启声音共享。
- 原生验证使用合成画面与本机 WebRTC，不能代替实际 Jitsi 服务版本、网络、设备和多屏组合的双端验收。

## 现场签收

使用待验收 Windows 包进入测试会议，另一端观看；记录客户端与 Web/Jitsi 部署版本、系统和显示器缩放比例。依次执行 AC-01 至 AC-15，暂停与切源需要同时记录共享端和观看端结果。所有本轮场景通过后再签收；批注始终排除。
