# Bundled OpenVPN Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship a Windows CloudMeet installer with OpenVPN and a local UI for importing profiles and choosing IPv4 VPN destinations.

**Architecture:** Electron local-shell IPC controls an independent OpenVPN manager. A fixed named-pipe bridge uses the official Interactive Service, authenticated management reports real tunnel state, and a bootstrapper installs signed vendor prerequisites without changing meeting configuration.

**Tech Stack:** Electron safeStorage, Node node:test/net/crypto, Windows PowerShell .NET named pipes, OpenVPN Community Interactive Service, WiX 3 Burn.

---

### Task 1: Profile/route policy (TDD)
- Create `scripts/openvpn-config.test.cjs`, run `node --test scripts/openvpn-config.test.cjs` and observe missing implementation failure.
- Create `src/openvpn-config.js`: strict inline-profile allowlist, IPv4 host/CIDR canonicalization, no default routes, external files or executable directives, explicit route generation and pull restrictions.
- Re-run until green, including malicious/unsupported profiles and boundary addresses.

### Task 2: Management protocol and lifecycle (TDD)
- Create `scripts/openvpn-management.test.cjs`, `scripts/openvpn.test.cjs` with fake transports and real temp stores; first observe failure.
- Create `src/openvpn-management.js`, `src/openvpn.js`, `src/openvpn-service.ps1` for authenticated loopback management, encrypted storage, current-user ACLs and fixed Interactive Service bridge.
- Test connected/reconnecting/exit/failure/authentication/timeout and cleanup. Never connect the developer host.

### Task 3: Local shell integration (TDD)
- Add `scripts/openvpn-panel.test.cjs`; observe missing panel failure.
- Add `src/openvpn-panel.js`; modify `src/index.html`, `src/preload.js`, `src/main.js`; leave existing system VPN controls intact.
- Verify local-source-only IPC and VM panel behavior for import/save/connect/errors/stale state.

### Task 4: Offline installer pipeline
- Add `scripts/build-openvpn-bundle.cjs`, `scripts/verify-openvpn-payload.cjs`, `vendor/openvpn/README.md` and payload metadata.
- Modify `forge.config.js` and `package.json` so Windows release make verifies vendor signature/hash and chains the official MSI with the generated CloudMeet MSI via WiX Burn.
- Native prerequisites must be pinned and verified, not guessed or fetched unsigned. A missing payload is a release blocker, not a successful standalone installer.

### Task 5: Verification and operator docs
- Update `README.md` and acceptance docs, clearly distinguish tested behavior from native unverified behavior.
- Run `npm run test:vpn`, new OpenVPN test suite, JS syntax checks, and installer preflight. Review `git diff --check` and final diff.
- Real install/driver/route/tunnel validation only with explicit authorization and a test server. Do not claim completion of these gates from mocks.
